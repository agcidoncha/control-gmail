Manual para explicar el proyecto

Cómo funciona el Asistente Comercial, de principio a fin.

Esta aplicación convierte el trabajo diario con Gmail en un espacio comercial ordenado: cada comercial trabaja con su propia cuenta, revisa lo importante, puede responder o redactar mensajes y recibe ayuda de IA para detectar oportunidades, seguimientos y compromisos.

01 · Resumen rápido

La explicación para alguien que pregunta: «¿qué habéis construido?»

Puedes explicar el proyecto con estas palabras. No hace falta hablar de Docker, OAuth o bases de datos en la primera conversación.

«Es una herramienta comercial conectada a Gmail. Ordena los correos de cada comercial, permite actuar sobre ellos y usa inteligencia artificial para convertir conversaciones en información útil: clientes, seguimientos y compromisos. La aplicación respeta la privacidad: cada persona solo ve su propia cuenta.»
1

Revisa lo importante

La bandeja muestra recibidos, enviados, hilos completos, filtros, papelera y acciones como marcar, archivar o responder.

2

Actúa desde el mismo lugar

El comercial puede responder a un hilo o escribir un correo nuevo. Antes de enviar se muestra una vista previa y se pide confirmación.

3

Convierte correo en trabajo

El sistema ayuda a localizar clientes, seguimientos y compromisos para que el correo no se quede en una bandeja sin organizar.

Lo importante: no sustituye Gmail ni decide por el comercial. Es una capa de trabajo comercial encima de Gmail, con controles y revisión humana.

03 · Usuarios y seguridad

Quién puede entrar y qué puede ver

La empresa tiene usuarios autorizados, pero autorizar a una persona no significa darle acceso al Gmail de otra.

Inicio con Google

La persona pulsa «Entrar con Google». Google autentica la identidad y devuelve un código temporal al servidor.

Validación OAuth

El backend comprueba el estado de seguridad, intercambia el código por tokens y consulta el perfil de Gmail autorizado.

Sesión propia

Se crea una sesión firmada y protegida. A partir de ese momento, las rutas privadas obtienen el email desde la sesión, no desde la URL.

Cuenta Gmail vinculada

Las llamadas a Gmail buscan los tokens cifrados de esa cuenta. Si la sesión es de dev@, la aplicación trabaja con dev@.

Administrador

Puede autorizar o eliminar usuarios, asignar rol, desconectar accesos y configurar la conexión de IA de empresa.

Puede administrar No lee Gmail ajeno

Comercial

Puede trabajar con su cuenta autorizada, revisar sus correos, responder, redactar y usar las funciones disponibles para su organización.

Trabaja con su cuenta No ve otras cuentas

Privacidad fundamental: incluso el administrador no puede leer los correos de otros usuarios desde la aplicación. Puede gestionar quién tiene acceso, pero no recibe el contenido privado de esas cuentas.

04 · Gmail y sincronización

Qué ocurre cuando se abre la bandeja

La aplicación no muestra una fotografía inventada: consulta y mantiene una copia de trabajo para que la experiencia sea rápida y controlable.

1. Se identifica la cuenta activa

La sesión indica qué cuenta Gmail está conectada. Esa cuenta es la única fuente válida para la operación.

2. Se sincronizan mensajes

El backend pide a Gmail recibidos, enviados o papelera según la pantalla y guarda metadatos normalizados en MySQL.

3. La interfaz muestra el resultado

La bandeja presenta hilos, fechas, remitentes, asunto, etiquetas de trabajo y estado de actualización.

4. Se puede actualizar manualmente

«Actualizar Gmail» fuerza una nueva sincronización. También existe una actualización automática de seguridad, pero el usuario puede pedirla al entrar o cuando lo necesite.

Recibidos y enviados

La bandeja comercial permite revisar mensajes de entrada y salida, buscar y abrir el hilo completo.

Responder y nuevo correo

El backend construye el mensaje, mantiene el hilo cuando corresponde y exige revisión explícita antes de enviarlo.

Papelera

La papelera utiliza la etiqueta de Gmail correspondiente. Desde ahí se puede restaurar según las acciones soportadas.

Por qué importa la fecha de actualización: si el usuario acaba de recibir un correo y la aplicación no se ha sincronizado, el análisis podría no verlo. Por eso la interfaz debe mostrar cuándo se actualizó y ofrecer una acción manual clara.

ArchivarQuita el mensaje de recibidos sin borrarlo.Confirmación de la interfaz y auditoría

05 · Inteligencia artificial

La IA ayuda a pensar; el comercial decide

La aplicación puede usar OpenAI o Claude mediante un adaptador común. El proveedor recibe solo el contexto autorizado de la cuenta activa y nunca decide acciones de Gmail por su cuenta.

Pregunta del comercialEj.: «¿Qué seguimientos están pendientes?»
→
BackendSincroniza, limita el alcance y prepara contexto
→
OpenAI o ClaudeAnaliza el contexto recibido
→
Resultado revisableHechos · inferencias · acciones

OpenAI

Es la opción práctica para análisis habituales de correo: resúmenes, clasificación, seguimientos y consultas comerciales. El coste depende del modelo y de la cantidad de texto enviado.

Uso habitual

Claude

Puede reservarse para análisis largos o especialmente complejos. No hace falta usarlo para cada búsqueda sencilla.

Uso especializado

Cómo se controla el coste

Ventana temporal

Por defecto se analizan los últimos 30 días. Ampliar a meses o años aumenta el contexto y el coste.

Alcance del buzón

Se puede analizar bandeja y enviados. Incluir archivados o spam debe ser una decisión consciente.

Límite de mensajes

Existe un límite de protección para no enviar una bandeja completa al modelo sin control.

La salida nunca es una verdad automática: la interfaz separa hechos, inferencias, acciones propuestas y fuentes, y muestra «requiere revisión humana» cuando corresponde.

Resumir conversaciones largasReducir un hilo a los puntos principales y próximos pasos.No sustituye la revisión del mensaje original.
Interpretar necesidadesSeparar señales comerciales, hechos e inferencias.No inventa clientes si el buzón solo contiene newsletters.

Se trabaja en local

Se cambia el código, se ejecutan las pruebas y se revisa visualmente la aplicación en localhost.

Se confirma una versión

Se hace commit con un mensaje claro. El commit identifica exactamente qué se ha probado.

09 · Copias y recuperación

Qué pasa si algo se rompe

Una copia solo es útil si se puede restaurar. Por eso ya hemos probado una restauración real en una base temporal sin tocar producción.

Copia automática

scripts/backup-mysql.sh genera un archivo comprimido de MySQL. El cron del VPS lo ejecuta cada día y conserva las copias dentro del periodo configurado.

Configurado

Prueba de restauración

La copia se importó en restore_check_20261013, aparecieron las 8 tablas esperadas y después se eliminó la base temporal.

Verificado

Qué protege

Usuarios, organización, conexiones, mensajes sincronizados, hilos y auditoría almacenados en MySQL.

Qué todavía hay que madurar

Separar copias fuera del VPS, probar recuperación completa del volumen y documentar un procedimiento de emergencia con tiempos objetivo.

Siguiente mejora

1. Detener o aislar el servicio afectado
2. Conservar la copia original
3. Crear una base temporal o un entorno aislado
4. Importar y comprobar tablas y datos
5. Solo después valorar una recuperación de producción
6. Registrar qué ocurrió y qué se ha recuperado
Principio: nunca probamos una restauración directamente encima de la base real si podemos hacerlo en un entorno temporal.

10 · Cómo se mantiene

La rutina segura para seguir desarrollando

Elegir un bloque pequeño

Por ejemplo: mejorar la UX de clientes o añadir el botón de actualizar Gmail. No mezclar cinco cambios grandes.

Implementar en local

Modificar código, comprobar la pantalla en navegador y probar el caso normal y el caso de error.

Ejecutar controles

npm test, npm run build y, si afecta a Docker, construir el contenedor.

Commit y push

Guardar una versión identificable en GitHub. El despliegue remoto debe corresponder a ese commit.

Verificar remoto

Comprobar healthchecks, login, pantalla afectada y una acción real no destructiva. Si algo falla, parar antes de seguir añadiendo funciones.

12 · Preguntas frecuentes

Respuestas sencillas para las dudas habituales

¿Esto reemplaza Gmail?

No. Gmail sigue siendo el servicio de correo y Google sigue almacenando los mensajes. La aplicación es una interfaz comercial especializada que trabaja sobre la cuenta autorizada.

¿Puede el administrador leer el correo de un comercial?

No desde esta aplicación. El administrador puede gestionar la autorización y el rol, pero cada sesión consulta exclusivamente la cuenta Gmail que la propia persona ha autorizado.

¿Dónde están los correos?

El original está en Gmail. La aplicación mantiene una copia de trabajo de los datos necesarios para presentar la bandeja, relacionar hilos y ofrecer análisis. Esa copia se guarda en MySQL en remoto.

¿Qué es EasyPanel?

Es el panel visual que administra los contenedores Docker del VPS. Permite ver y desplegar frontend, API y MySQL sin tener que ejecutar cada operación desde el terminal.

¿Qué es Traefik?

Es la puerta de entrada web del VPS. Recibe una petición para lab.thelocalhost.es, la envía al frontend correcto y gestiona el acceso HTTPS.

¿Qué es MySQL?

Es la base de datos estructurada. Guarda usuarios, sincronización, acciones y datos normalizados; no es el servidor de correo.

¿Por qué no se puede hacer todo solo con el frontend?

Porque el navegador no debe tener autoridad para elegir otra cuenta, leer tokens o saltarse permisos. Esas decisiones deben estar en el backend.

¿Cuándo se puede ofrecer a clientes?

Cuando el almacenamiento de secretos, backups fuera del VPS, recuperación, límites de consumo, privacidad y despliegue estén revisados con usuarios reales. La funcionalidad es prometedora, pero vender requiere ese último nivel de garantía.

Frase final: es un espacio comercial seguro sobre Gmail: cada comercial trabaja con su propio correo, la aplicación ordena el trabajo y la IA ayuda a priorizarlo, pero las decisiones importantes siguen en manos de la persona.
